# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Grace period logic checked `minutes > 10` after integer floor division. Also timezone naive/UTC handling was incorrect and overnight shifts were not supported. | For shift `09:30`, punching in at `09:40:01` (601s elapsed) yielded `0` late minutes instead of `10` (violating R2). | Truncated seconds, converted to IST, evaluated `elapsed_seconds > 600`, and floored whole minutes since shift start (`elapsed // 60`). |
| 2 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round(..., 2)`, which implements banker's rounding (round half to even) instead of standard round half-up. | Durations like `2.675` hours rounded down to `2.67` instead of `2.68` (violating R4). | Used Python's `Decimal` with `ROUND_HALF_UP` on whole-second truncated durations. |
| 3 | `compute_overtime` (lines 44-48) | Missing 30-minute minimum threshold; overnight shift end calculation used `date_str` directly; mixed naive UTC datetime with timezone-aware IST datetime. | Punch-out with 5 min overtime returned 5 instead of 0 (R3); overnight shift 22:00-06:00 computed 16+ hours overtime; crashed with `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Added 30-min threshold (`diff >= 1800`), projected overnight shift end to next calendar day (`date + 1 day`), and normalized timestamps in IST. |
| 4 | `POST /employees` (lines 77-85) | Check-then-insert concurrency race condition; missing validation for `shift_start != shift_end`; returned `created_at` as a datetime rather than epoch milliseconds. | Concurrent identical requests created duplicates or threw unhandled `DuplicateKeyError` (500); creating employee with `09:30`/`09:30` returned 201 instead of 422; schema validation failed on `created_at`. | Handled `DuplicateKeyError` returning 409, added model validation rejecting identical shift times (422), and converted `created_at` to integer epoch ms. |
| 5 | `GET /employees` (lines 88-96) | Off-by-one pagination `skip = page * page_size`; `total` counted the whole collection instead of the filtered subset; missing ascending sort on `emp_code`. | Requesting `page=1` skipped the first 20 records; filtering by `department="Engineering"` showed total count of all company employees; results were unordered. | Set `skip = (page - 1) * page_size`, computed `count_documents(q)` with filter, and added `.sort("emp_code", 1)`. |
| 6 | `POST /attendance/punch-in` (lines 99-121) | Crash on unknown employee; check-then-insert race condition; missing R1 overnight attendance date assignment; unvalidated `status`; returned illegal `id` field and datetime object. | Unknown `emp_code` caused `TypeError: 'NoneType' object is not subscriptable` (500) instead of 404; concurrent punch-ins created duplicate logs; overnight shift punches before shift end were logged on wrong day; output failed OpenAPI contract. | Checked employee existence (404), enforced unique compound index `(emp_code, date)` catching duplicate key (409), implemented R1 overnight date logic, validated status enum (422), and returned compliant `AttendanceRecord` schema. |
| 7 | `GET /attendance` (lines 124-150) | In-memory `list(...)` fetch and Python sort caused severe latency and memory exhaustion on large datasets; omitted `date_from > date_to` validation; missing secondary sort; injected forbidden `id` field; missing default values for legacy docs. | Querying 100k records ran out of memory / took seconds; `date_from=2026-07-31&date_to=2026-07-01` returned 200 instead of 422; tied dates lacked stable ordering; missing `history`/`half_day` broke client schema validation. | Handled queries and pagination entirely inside MongoDB with `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)` backed by compound index, validated date bounds (422), and sanitized output format. |
| 8 | `GET /health` (lines 72-74) | Probe returned static `{"status": "ok"}` 200 without checking MongoDB connectivity. | Stopping MongoDB still resulted in `/health` returning 200 OK. | Executed `client.admin.command('ping')`, catching exceptions and returning HTTP 503. |
| 9 | Lifecycle & Indexes (startup) | No database indexes created at application startup. | Queries on 100k documents performed full collection scans (`COLLSCAN`), and database could not guarantee unique constraints under concurrency. | Added idempotent startup index initialization in FastAPI `lifespan` for all query, uniqueness, and sorting patterns. |

## Examined and Decided Not Defect

- **FastAPI app title and version:** Configured as `title="Employee Attendance & Analytics API", version="2.0.0"`. Matches the OpenAPI specification header exactly.
- **`load_dotenv()` usage:** Starter loaded `.env` at module import. We ensured `load_dotenv(override=False)` is used so real environment variables (`MONGO_URI`, `MONGO_DB`) strictly take precedence while preserving local developer convenience.
